# Agent prompt: use Creative Pixels to edit video

Use the Creative Pixels MCP tools whenever the user asks you to edit, create, render, or analyze a Pixels video project.

The MCP server is named `creative_pixels`. Its tools are prefixed `mcp_creative_pixels_*`.

## Always follow this workflow

1. If you need media that isn't already imported, call `mcp_creative_pixels_pixels_import_media` with the absolute file path.
2. Call `mcp_creative_pixels_pixels_capabilities` if you need to know supported edit ops, GPU effects, codecs, or schemas.
3. For a new project, call `mcp_creative_pixels_pixels_create_project` with name, width, height, fps.
4. For an existing project, call `mcp_creative_pixels_pixels_get_project` first to read the current timeline/revision.
5. Use `mcp_creative_pixels_pixels_edit_project` for all timeline changes. Every op must have a unique `callerId`. Reference ids generated by earlier ops using `{ "$ref": "callerId#/detail/..." }`.
6. Use `mcp_creative_pixels_pixels_render_project` to export. Default output is a temp file; the tool returns the final path.

## Tool-specific rules

- `pixels_edit_project` ops:
  - `addClip` needs a mediaId already imported into the workspace.
  - Video clips create linked audio companions automatically.
  - `addText` supports `text`, `from`, `durationInFrames`, `color`, `fontSize`, `fontFamily`, `fontWeight`, `textAlign`, `verticalAlign`.
  - `addEffect` requires a valid `gpuEffectType` from `pixels_capabilities` and `params`.
  - `setTransform` accepts `x`, `y`, `width`, `height`, `rotation`, `opacity`, `cornerRadius`, `flipHorizontal`, `flipVertical`.
  - To split/trim, first get the clip id, then call `split`, `trimStart`, or `trimEnd`.
- `pixels_render_project`: if the user doesn't specify codec/container/quality, default to `codec: h264`, `container: mp4`, `quality: high`.
- Always report the output file path, file size, duration, and any warnings returned by the render tool.

## Safety notes for agent editing

- Workspace folders must be local and non-cloud-synced. Cloud-synced folders cause File System Access API stale-handle errors.
- GPU effects require a real WebGPU adapter. If on a machine with only software WebGPU, refuse GPU-effect renders and warn the user.
- Do not render to cloud-synced or network paths.

## Example request handling

User: "Make a 5-second Pixels clip from /Users/me/clip.mp4 with a text intro saying 'Demo'."

Plan:
1. `pixels_import_media` on `/Users/me/clip.mp4`.
2. `pixels_create_project` named "Demo" with matching width/height/fps (or ask if unknown).
3. `pixels_edit_project` with ops:
   - `addTrack` (video)
   - `addClip` referencing imported media
   - `addText` at frame 0 for ~1.5 sec (fps * 1.5 frames)
4. `pixels_render_project` with `duration: 5`.
5. Report output path + metadata.
